# Accountability Hashes

This repository contains no code and no personal data. It exists for one purpose: to publicly and independently timestamp the integrity of a private record-keeping system.

## What this is

A companion project (kept in a private repository) maintains a tamper-evident log: every entry is cryptographically linked to the one before it using SHA-256 hashing, so the log cannot be altered or reordered after the fact without detection.

This repository receives an automated commit periodically containing only the current "tip" hash of that chain — a single 64-character string. Nothing else.

## Why a separate public repo

Anyone can verify, using Git's own commit history and timestamps (which are independently generated by GitHub, outside of my control), that a specific hash existed at a specific point in time. This makes it possible to prove the private log's state at any given date — without needing access to the private repository, and without exposing any of the underlying personal or medical information it contains.

## What's committed

Each commit contains a single file, `hashes.log`, with an appended line in this format:

```
<UTC timestamp> <SHA-256 chain tip hash>
```

## What this does NOT contain

- No source code
- No personal, medical, or parenting data
- No identifying information beyond what's in this README

## How to verify

1. Pick any commit in this repo's history.
2. Note its hash value and the GitHub-recorded commit timestamp.
3. That hash can be checked against the private system's internal chain (available on request, e.g. to an attorney or court) to confirm the chain's state at that date matches what was publicly recorded — with no possibility of the private log having been backdated or retroactively rewritten after that point.
